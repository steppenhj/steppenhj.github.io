Architecture & Design

Neuro-Drive-C++ 시스템의 요구사항, 데이터 흐름, 그리고 하드웨어-소프트웨어 통합 구조를 설계한 다이어그램입니다.

PHASE 06

CAN Multi-ECU 분산 제어 아키텍처

RPi5 + F446RE + F411RE · CAN 500kbps · bxCAN / MCP2515(SPI) · StarUML

1. System Structure (Block Definition Diagram)

3노드 CAN 버스 아키텍처의 하드웨어·소프트웨어 통합 구조를 정의한 블록 다이어그램입니다.

  • CAN Interface: F446RE는 내장 bxCAN, RPi/F411RE는 MCP2515(SPI-CAN)으로 동일 버스 참여
  • Transceiver: 전 노드 TJA1050 트랜시버 사용, 120Ω 종단저항 양단 배치
  • Sensor Logic: 50ms 폴링 + 임계값(20cm) 기반 하이브리드 전송 설계

2. CAN Message Flow (Sequence Diagram)

WebUI부터 센서 ECU까지의 CAN 메시지 흐름과 장애물 감지 시나리오를 시간 순으로 설계했습니다.

  • Motor Control: RPi → F446RE, 0x100 MotorCMD (CAN, 50ms 주기)
  • Sensor Periodic: F411RE → All, 0x300 SensorData (CAN, 100ms 주기)
  • Obstacle Response: F446RE가 CAN 수신으로 자체 판단 후 즉시 정지 — 마스터 거치지 않는 안전 설계
  • alt Fragment: 장애물 감지(distance < 20cm) vs 정상 주행 분기 표현
PHASE 01 – 05

UART 기반 단일 ECU 아키텍처

RPi5 ↔ STM32F411RE · UART 115200bps · FreeRTOS · MBSE

3. System Requirements (Use Case)

시스템의 바운더리와 외부 액터(Operator, Hardware) 간의 상호작용을 정의했습니다.

  • Core Feature: 조이스틱 조작, 엔진 토글, 텔레메트리 모니터링
  • Safety Logic: 통신 두절 시 하드웨어를 강제 통제하는 Execute Fail-safe 설계
  • Control Logic: 조향 시 마찰 저항을 상쇄하는 Cornering Boost 내부 로직 포함

4. Data Flow & IPC (Sequence)

① Command Flow (Control Path)
② Encoder Feedback Path

Web Front-end부터 STM32 펌웨어까지 이어지는 이기종 간의 제어 명령 전달 과정을 시간 순으로 설계했습니다.

  • Web → Py: JSON 포맷의 WebSocket 통신
  • Py → C++: struct.pack을 이용한 8-byte 이진 데이터 UDP 송신
  • C++ → STM32: 115200bps UART 기반 ASCII String 시리얼 통신
  • STM32 내부: UART 인터럽트 수신 후 FreeRTOS Message Queue 삽입 및 처리
  • STM32 → Web: 엔코더 속도값 printf("ENC:%d") → C++ UDP 역전송 → WebSocket

5. System Structure (Class / BDD)

Raspberry Pi와 STM32, 그리고 하드웨어 액추에이터가 결합된 전체 시스템의 정적 구조(Topology)입니다.

  • Composition: NeuroDrive 최상위 시스템이 각 하위 모듈을 소유(has-a)하는 토폴로지 구성
  • High-Level: 통신망(WebSocket, UDP)과 상위 제어(Linux) 명시
  • Low-Level: 실시간 제어(FreeRTOS) 및 하드웨어 통신 인터페이스(UART) 분리 설계
  • Power & Actuator: 구동을 위한 전압(7.4V) 조향 및 구동 액추에이터 명세 포함

6. Model-Based System Engineering (MBSE)

수동으로 작성(Hand-coded)했던 C++의 복잡한 스레드(Thread)와 자물쇠(Mutex) 동기화 로직을 IBM Rhapsody를 활용해 이벤트 구동(Event-Driven) 기반의 상태 머신으로 고도화 및 재설계한 모델입니다.

[1] Object Model Diagram (OMD)
  • Active Class: UdpReceiver와 VehicleController를 독립된 스레드를 가지는 활성 클래스로 정의
[2] Statechart Diagram (Behavior)
  • State Machine: 제어기의 동작을 INIT, OPERATING, FAIL_SAFE 상태로 명확히 분리 (Switch-Case 구조 자동 생성)
  • Timeout Watchdog: 기존 while 루프 내의 시간 연산(Polling) 로직을 랩소디 내장 이벤트인 tm(500) 트리거 하나로 완벽히 추상화하여 Fail-safe 신뢰성 향상
