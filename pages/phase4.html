RTH State Machine

RTH는 3개의 모드(mode)로 동작합니다. 웹 UI의 버튼 하나로 상태가 순환하며,
각 모드는 통신 프로토콜의 mode 필드를 통해 전체 스택에 전파됩니다.

🟢

mode = 0

NORMAL

일반 주행
조이스틱 명령 수행

🔴

mode = 1

REC (Recording)

경로 기록 중
엔코더 수신마다 Stack Push

↩️

mode = 2

RTH (Returning)

자동 복귀 중
Stack Pop → 역방향 명령

Protocol Extension

Context: RTH 상태를 모든 레이어에 전파하기 위해 기존 8바이트 UDP 패킷에 mode 필드를 추가했습니다.

Protocol Change
// Before: 8 bytes
struct Packet { float th; float st; };

// After: 12 bytes (+mode field)
struct Packet { float th; float st; int mode; };

# Python side
struct.pack('ffi', throttle, steering, mode)

Path Stack (LIFO)

Context: GPS/IMU 없이 엔코더 이벤트마다 {방향, 조향각}을 기록하고, 복귀 시 역순으로 꺼냅니다.

SharedContext (C++)
// 경로 데이터 구조
std::vector<std::pair<int, int>> path;
// pair = {encoder_diff, pwm_angle}
// encoder_diff: 실제 이동 거리 (부호=방향)
// pwm_angle: 서보 조향각 (1500±900)

// REC: push_back (FIFO 순서 기록)
// RTH: pop_back (LIFO 역순 복귀)
// → 스텝별 거리 P-제어로 감속 정지

Core Logic: Record & Return

모든 RTH 로직은 controlLoop() 안에서 엔코더 수신 이벤트를 트리거로 동작합니다.

  • Recording (mode=1): 엔코더 수신 시 {실제 이동 거리(enc_diff), 조향각}을 path에 push. 노이즈 필터(|enc| > 2)로 정지 구간의 미세 진동 제외.
  • Returning (mode=2): path에서 pop → 거리 기반 P-제어로 복귀. 남은 거리에 비례하여 감속(min(600, max(500, remaining×3))). 목표 거리 도달 시 다음 스텝 로드. 워치독 timeout 시 즉시 중단.
  • Done: path가 비면 rth_mode=0으로 복귀 후 정지 명령 전송.
control_core_oop.cpp
// 1. [REC] 엔코더 수신 시 경로 기록
if(rth_mode == 1 && abs(enc_val) > 2) {
  // 노이즈 필터: 최소 이동량 이상만 기록
  path.push_back({enc_val, pwm_angle});
}

// 2. [RTH] 거리 기반 P-제어 복귀
if(rth_mode == 2 && !timeout) {
  auto [target, angle] = path.back();
  path.pop_back();
  rth_target = abs(target);
  
  // 엔코더 누적 → 남은 거리 비례 감속
  rth_acc += abs(enc_val);
  int remaining = rth_target - rth_acc;
  int spd = min(600, max(500, remaining * 3));
  write(serial_fd, spd * direction, angle);
}

Watchdog Integration

RTH 복귀 중에도 워치독은 항상 동작합니다. 500ms 이상 패킷이 끊기면 RTH도 즉시 중단되어, "복귀 중 2차 사고"를 방지합니다.

control_core_oop.cpp
// RTH 중에도 워치독 적용
if(rth_mode == 2 && !timeout) {
  // timeout이면 이 블록 진입 불가
  // → RTH 자동 중단, 차량 정지
}

Keep-Alive Task

RTH 버튼을 누르면 단발성 패킷만 전송됩니다. 그 상태로 두면 500ms 후 워치독이 발동하여 RTH가 중단됩니다. 이를 방지하기 위해 Python에서 100ms 주기 Keep-Alive 패킷을 전송합니다.

app.py
def rth_keep_alive_task():
  while True:
    if rth_active:
      send_udp_command(0.0, 0.0, 2)
    socketio.sleep(0.1) # 100ms

Engineering Challenges

Watchdog vs RTH 충돌

Problem: RTH 버튼 클릭 → 단발 패킷 → 500ms 후 워치독 발동 → RTH 중단.
Solution: Python 백그라운드에서 100ms 주기 Keep-Alive 패킷을 지속 전송.

노이즈 & 과주행 방지

Problem: 정지 상태에서도 엔코더 미세 진동 기록 → 복귀 시 불필요한 이동 발생.
Solution: if(abs(enc_val) > 2) 노이즈 필터 + 거리 기반 P-제어로 목표 거리 도달 시 정확히 정지.

Thread-Safety

Problem: UdpReceiver와 controlLoop가 path에 동시 접근 가능.
Solution: std::mutex path_mutex 도입 + std::atomic<int> rth_mode로 lock-free 상태 전파.

박해진's Note

"처음엔 IMU + GPS로 정밀한 RTH를 구상했지만, 현재 하드웨어 조건에서는 오히려 단순한 접근이 더 신뢰성 있다고 판단했습니다.
엔코더의 방향(sign)과 조향각만으로 경로를 기록하고, Stack의 LIFO 특성을 그대로 활용하여 역추적하는 방식은
구현이 간결하면서도 워치독, 프로토콜 확장, Keep-Alive 등 실제 시스템 통합에서 마주치는 엔지니어링 문제를 모두 해결해야 했습니다."
