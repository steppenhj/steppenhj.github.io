Issue 1: Pin Muxing

HAL 라이브러리 초기화 실패로 인한 PWM 출력 불가 현상.
GPIO 레지스터를 직접 조작하여 해결했습니다.

Solution: Force_Hardware_Config();

Issue 2: Thread Race Condition

웹 서버 요청(Read)과 상태 모니터링(Write) 스레드가
단일 시리얼 포트에 동시 접근하여 충돌 발생.

[Error] SerialException: device reports readiness to read but returned no data
Latency: > 500ms (Critical)
Solution Semaphore Lock & Eventlet

공유 자원(UART) 접근 시 Semaphore로 상호 배제(Mutex)를 구현하고, Non-blocking I/O로 스레드 블로킹을 방지했습니다.

Issue 3: Encoder Bring-up

수동 주행은 정상인데 엔코더(ENC)가 0으로 고정되는 문제를 “펌웨어 기반 계측”으로 해결.

Symptom: ENC always 0 → raw counter not moving
Solution TIM1 Clock Enable + Counter Reset

PC에서 UART 로그로 “ENC:0” 고정 확인 → PA8/PA9를 GPIO 입력으로 임시 전환해 A/B 토글 검증 → TIM1 클럭 enable 및 카운터 초기화로 카운트 정상화.

Result & Engineering Insight

Phase 1(Linux C++)과 비교했을 때 평균 Latency는 약 10ms 내외로 비슷하지만, 가장 큰 성과는 "예측 가능한 제어(Deterministic Control)"를 확보했다는 점입니다.

  • Measurement: 시스템 로그(Timestamp) 분석 결과, 스레드 충돌 해결 후 안정적인 통신 확인.
  • Benefit: 모터 제어 부하를 MCU로 이관함에 따라, 향후 Phase 3(자율주행 AI) 도입 시 라즈베리파이의 연산 자원을 온전히 영상 처리에 집중할 수 있게 되었습니다.
