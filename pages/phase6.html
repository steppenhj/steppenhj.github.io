PHASE 06: FIRMWARE UPDATE

OTA & Bootloader

유지보수 효율성을 극대화하기 위해, JTAG/ST-Link 없이도
라즈베리파이를 통해 STM32의 펌웨어를 원격으로 업데이트하는 OTA(Over-The-Air) 시스템을 구축했습니다.

System Architecture

차량(RC카)이 주행 불가능한 위치에 있거나 케이스를 분해하기 어려운 상황에서도 소프트웨어 패치(Bug fix)가 가능해야 합니다. 이를 위해 Custom Bootloader를 개발했습니다.

0x0800 0000 Bootloader (16KB)
0x0800 4000 Application (User Code)

Update Sequence

  1. Trigger: RPi가 UART로 "UPDATE_REQ" 커맨드 전송
  2. Reset: STM32가 이를 감지하고 Soft Reset 수행
  3. Bootloader Mode: 부트로더가 실행되어 대기 상태 진입
  4. Flash Erase: App 영역(Sector 1~)을 삭제
  5. Data Stream: RPi로부터 바이너리(.bin) 수신 및 기록
  6. Verify & Jump: CRC 검증 후 App 주소로 점프
bootloader_main.c 
// Jump to Application Function
void JumpToApp(void) {
    uint32_t JumpAddress = *(__IO uint32_t*) (APP_ADDRESS + 4);
    
    // 1. Disable all interrupts
    __disable_irq();
    
    // 2. Set Vector Table Offset
    SCB->VTOR = APP_ADDRESS;
    
    // 3. Jump to Reset Handler
    Jump_To_Application = (pFunction) JumpAddress;
    Jump_To_Application();
}

Why IAP (In-Application Programming)?

제조 현장이나 실제 운용 환경에서는 물리적 연결(JTAG)이 어렵습니다. 통신 인터페이스(UART, CAN, WiFi)를 통해 펌웨어를 자체적으로 업데이트하는 기술은 전장(Automotive) 및 IoT 분야의 핵심 요구사항입니다.
