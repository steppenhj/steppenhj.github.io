Layer 1: The Gateway

웹에서의 비동기 요청을 받아 안전장치(Safety Lock)를 거친 후, C++ 코어가 이해할 수 있는 Binary Packet으로 압축하여 전송합니다.

app.py
if not engine_running: return # Safety Gate

# float(4byte) 2개를 8byte 패킷으로 압축
packet = struct.pack('ff', throttle, steering)
sock.sendto(packet, (UDP_IP, UDP_PORT))

Layer 2: The Core

Multi-threading 구조입니다. 수신(Receiver) 스레드와 제어(Control) 스레드가 Mutex를 통해 데이터를 안전하게 공유하며 하드웨어(UART)로 명령을 쏘아줍니다.

control_core.cpp
// Thread 1: Receiver (Locking)
lock_guard<mutex> lock(data_lock);
shared_data = packet;

// Thread 2: Controller (Non-blocking Write)
snprintf(buf, ... "%d,%d\n", speed, angle);
write(serial_fd, buf, len);

Layer 3: RTOS & Queue (STM32)

인터럽트(ISR)의 처리 시간을 최소화하기 위해 생산자-소비자 패턴(Producer-Consumer)을 적용했습니다.

  • Producer (ISR): UART로 데이터가 오면 즉시 Queue에 넣고 종료 (Latency < 10us).
  • Consumer (Task): 모터 태스크가 Queue를 감시하다가 데이터가 있으면 꺼내서 PID 제어 수행.
  • Decoupling: 통신 속도와 제어 속도의 차이를 완충(Buffer).
main.c (RTOS Pattern)
// 1. [Producer] UART Interrupt (Fast)
void HAL_UART_RxCpltCallback(...) {
  // 큐에 넣고 즉시 복귀 (Non-blocking)
  osMessageQueuePut(cmdQueue, &data, ...);
}

// 2. [Consumer] Motor Task (Heavy)
void StartMotorTask(...) {
  while(1) {
    // 데이터가 올 때까지 대기 (Sleep)
    osMessageQueueGet(cmdQueue, &msg, ...);
    PID_Calculate(msg.speed); // 복잡한 연산 수행
  }
}

Performance Verification

RTOS와 인터럽트 큐(Queue)를 도입하여 구조 복잡도는 증가했지만, 결과적으로 "예측 가능한 제어(Deterministic Control)"를 달성했습니다.

Test Scenario:

Host(노트북)에서 고속으로 랜덤한 주행 명령을 쏟아붓는 상황(Stress Test)에서도, STM32가 100Hz 주기를 놓치지 않고 즉각 반응하는 것을 확인했습니다.
