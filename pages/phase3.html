RTOS Task Architecture

단일 루프(Super Loop)의 한계를 넘어, 선점형 멀티태스킹과 인터럽트를 도입했습니다.

Context Type Priority Role
ISR (UART) Hardware Highest Data Reception & Queue Push
Safety_Task Realtime High Emergency Stop check
Motor_Task Normal Mid Queue Consumer & Control

Key Logic: Event-Driven (Interrupt)

기존 Polling 방식의 CPU 낭비를 제거하기 위해 UART Rx Interrupt를 적용했습니다. 데이터가 도착했을 때만 하드웨어 인터럽트가 발생하여 큐에 데이터를 넣고, 평소에는 CPU가 다른 작업에 집중합니다.

stm32_it.c (Interrupt Service Routine)
// UART 수신 완료 시 하드웨어가 자동 호출 (Callback)
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    
    // 1. Parse Data immediately
    if (parse_packet(buffer, &cmd)) {
        
        // 2. Push to Queue (Non-blocking form ISR)
        // 인터럽트 컨텍스트에서 안전하게 큐 전송
        osMessageQueuePut(myQueueHandle, &cmd, 0, 0);
        
        // 3. Trigger Debug LED
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    }

    // 4. Re-arm Interrupt (다음 수신 대기)
    HAL_UART_Receive_IT(&huart2, &rx_data, 1);
}

박해진's Note

"RTOS를 도입하며 가장 크게 배운 것은 '기다림의 미학(Blocking)'과 '사건 중심(Event-Driven)' 사고방식입니다.
데이터가 오는지 계속 감시하던(Polling) 비효율적인 구조를 버리고, 하드웨어가 신호를 줄 때만 반응하는 인터럽트 구조로 변경함으로써 시스템의 응답성과 효율성을 동시에 잡을 수 있었습니다. 이것이 바로 자원을 극한으로 아껴야 하는 임베디드 시스템의 본질임을 깨달았습니다."
