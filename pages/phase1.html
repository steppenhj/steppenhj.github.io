Why WebSocket?

Context: 웹 브라우저(Client) 파이썬 서버

  • Reason: HTTP는 클라이언트 요청 없이 서버가 데이터를 보낼 수 없는 단방향 구조입니다. 조이스틱 명령 전송과 동시에 서버가 텔레메트리/로그를 push해야 하므로, 양방향 실시간 통신이 가능한 WebSocket을 선택했습니다.

Why UDP?

Context: 파이썬 게이트웨이 C++ 엔진

  • Reason: 제어 명령은 항상 최신 값만 유효하므로, TCP의 재전송/순서보장 오버헤드가 불필요합니다. struct.pack('ff')로 8바이트 바이너리 전송 시 C++ 측에서 파싱 없이 즉시 사용 가능합니다.

C++: Hardware Watchdog

UDP 소켓 옵션을 활용하여 통신 두절을 감지하고, 비상시 즉시 액추에이터를 정지합니다.

drive_server.cpp (Fail-safe)
// Safety Layer 3: 500ms Timeout Watchdog
struct timeval tv = {0, 500000}; 
setsockopt(sock, SOL_SOCKET, SO_RCVTIMEO, ...);

while (true) {
    int n = recvfrom(sock, &data, ...);
    // 타임아웃 발생 시 즉시 정지
    if (n < 0) motors.stopAll(); 
    else motors.setSpeed(data.th);
}

Engineering Insight: OS Limitation

Python 대신 C++로 하드웨어 제어기를 작성하여 연산 효율을 높였지만, 범용 OS(Linux)는 구조적으로 Hard Real-time을 보장할 수 없습니다. 커널 스케줄러가 언제든 제어 프로세스를 선점할 수 있어, 안전이 요구되는 액추에이션을 OS 위에서 실행하는 것은 설계상 적절하지 않다고 판단했습니다.
