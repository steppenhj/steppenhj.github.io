Firmware: Pin Muxing Fix

HAL 라이브러리 초기화 과정에서 발생한 Pin Mapping(Muxing) 누락 문제를 해결했습니다. Force_Hardware_Config 함수를 직접 구현하여 타이머 신호를 실제 GPIO 핀(PA0/PB0)에 강제 할당함으로써 모터 제어 신호를 활성화했습니다.

// Force Pin Configuration (Solved Motor Issue) static void Force_Hardware_Config(void) { GPIO_InitTypeDef GPIO_InitStruct = {0}; __HAL_RCC_GPIOA_CLK_ENABLE(); // Connect TIM2(PWM) to PA0 Pin GPIO_InitStruct.Pin = GPIO_PIN_0; GPIO_InitStruct.Mode = GPIO_MODE_AF_PP; GPIO_InitStruct.Alternate = GPIO_AF1_TIM2; HAL_GPIO_Init(GPIOA, &GPIO_InitStruct); }

Middleware: Async Lock

Python Flask의 단일 스레드 구조로 인한 500ms 이상의 Latency 문제를 해결했습니다. Eventlet 비동기 라이브러리와 Semaphore(Lock)를 도입하여, 데이터 수신(Read)과 명령 송신(Write) 간의 충돌(Race Condition)을 방지하고 응답 속도를 10ms대로 최적화했습니다.

Engineering Log: Troubleshooting
Critical: Motor Driver Failure SOLVED

STM32에서 PWM 신호를 보내고 있음에도 모터가 작동하지 않는 현상 발생. 3.3V 직결 테스트를 통해 모터 드라이버(L298N)는 정상임을 확인.

Cause: Common Ground(공통 접지) 누락 및 Alternate Function 설정 부재
Fix: STM32 GND와 배터리 GND 연결 + Force_Hardware_Config() 구현
Critical: High Latency & UI Lag SOLVED

웹 컨트롤러 조작 시 500ms 이상의 지연 발생 및 온도 데이터 갱신 중단. 터미널 로그에 Serial Write Error 반복 확인.

Cause: Read/Write 스레드의 시리얼 포트 동시 접근 충돌
Fix: Eventlet 도입으로 Non-blocking I/O 구현 및 Semaphore Lock 적용
